# 第二大脑创建：非技术用户验收表

## 本表检查什么

本表用于 new-domain 本地“示例工程”试用。它把公开章程、原始流程与程序实现分开对应，帮助用户确认资料是否建对、是否能找到。命令运行成功不等于人工验收通过。

仓库可以理解为“有修改历史的项目文件夹”；第二大脑是将这些文件夹按统一规则组织起来的知识体系。插件创建初始结构、登记关联、填写基础说明并执行技术检查，具体业务知识需要后续持续积累。

## 规范依据

- A：资产章程 `quanttide-bylaw-of-asset-management/contract/public-second-brain.md`，版本 `0301294afc35297e2668119eb00248345ff55309`。第三至六条规定双轴与命名，第七条规定领域目录，第八条规定同类资产聚合。
- B：原始流程 `quanttide-profile-of-agent-engineering/quanttide-asset/contexts/second-brain-init.md`，版本 `2b5666c445237779f179d1e27ad23c08f069980d`。“标准流程”规定七个最小仓库、挂载、领域文档、根入口与验证；“格式与契约”“提交与协作规范”规定文档格式和许可等。
- C：本插件 local 演示约定。额外建立一个测试根仓库；实际 GitHub 根仓库已有时应复用。

“七个最小仓库”和领域 README 的具体要求来自 B，不应全部归称为 A 的明文条款。二十种资产是分类体系，不要求一开始建二十个仓库。

## 当前产品体验问题与改进标准

“在指导下跑完命令”和“非技术成员能独立顺利使用”需要分开记录。旧命令行版本存在需要理解命令、切换文件夹、阅读英文步骤与原始文件的问题。0.3.0 已提供中文向导和一页检查报告，仍需由真实用户评估是否足够易用。

当前中文向导提供一页结果：每条原标准、人话解释、预期值、实际值、检查证据、状态，以及可直接打开的对应产物。技术项依据实际检查显示通过或失败，未执行时不显示为通过；需要理解内容的项目保留“待本人验收”。不要让用户凭一个总 passed 推断全部合规。

“名称是否合理”“边界是否清楚”等内容判断保留给用户；仓库计数、命名匹配、目录和挂载等机械检查尽量自动化。未建立业务应用、未推送 GitHub等范围信息也应显示在同一页。
