# 第二大脑创建循环需求

## 目标与依据

将原始对话中可复用的领域第二大脑操作整理为给 AI 的 Skill、可执行配置及资产云入口。依据原始 Context、37 个用户回合和公开资产章程；来源固定版本见技能的 `assets/specification.yaml`。原始资料不改写。

## 职责

AI 理解自然语言、调查名称先例和组织规则、形成领域边界及完整影响清单。Python 执行器校验配置、调查仓库、生成具体计划、登记针对计划的确认、执行 Git 操作并验证。资产云登记文件描述资料路径，适配入口加载登记后调用执行器。

## 输入输出

输入为一个明确场景的 YAML、目标工作区、独立运行记录目录和 local 或 github provider。输出为可审阅计划、确认记录、实际仓库与文档、执行日志、验证报告和结果说明。

## 验收标准

1. 七类场景均有明确字段、实际操作与检查；自然语言判断由宿主 AI 完成。
2. 新建领域产生 7 个最小仓库与 6 个子模块，并更新已有根仓库；本地测试额外提供根仓库样本。
3. 缺少输入、计划变化、工作区漂移或未确认时拒绝执行。
4. 不覆盖已有人工内容和许可证，只暂存明确路径，按子仓库到根仓库提交推送。
5. 执行日志支持检查点恢复；重复生成同一目标计划不制造多余提交。
6. 技能可以整体复制，复制后执行器和校验程序不依赖原项目目录。
7. 资产云原生 CLI 能读取契约；专用入口能加载契约并完成实际流程。
8. 说明文档给出非技术用户的输入、审阅、结果阅读方式及维护者操作命令。
9. 测试记录保存真实环境、命令、输出与失败情况，区分模拟确认、真实 GitHub 操作和真实用户验收。

## 本版边界

配套仓库先建 README 骨架；文档内容的领域准确性需要人工审阅。更名只处理明确列出的配套资产英文后缀和引用仓库。官网建设、意图正文的专业撰写、云端网页安装按钮、跨组织自动发现与部署不包含在本版执行器中。GitHub provider 已实现，但真实账号联调未完成。
