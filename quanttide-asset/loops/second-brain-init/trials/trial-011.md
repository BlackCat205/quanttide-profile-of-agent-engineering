可复现入口：`tests/native_registration.py --cli <原生二进制> --source-commit <对应源码提交> --output <新证据目录>`。负例只修改临时副本，不修改真实插件、用户数据或 GitHub。

本次核对后无需改变登记结构；仅更新 UI 版本参数。Rust 解析器读取 assets 的 type/provider/metadata、skills 的 version/entrypoint/params 和 validation；不能宣称原生 CLI 会解释全部附加说明字段，也不能把其归档 run 当作通用技能调度器。

## 插件修改

- 新增自管测试组织输入；创建前核对当前用户的组织成员状态为 active、角色为 admin。非所有者或无法读取时停止。组织本身须预先存在，插件不代创建。
- 个人身份与目标组织分开保留，创建下一个领域仍使用选定组织及已有入口。
- 旧报告中的 ls-remote 失败按“无法核验”展示，保留原日志、报告时间和未通过结论，不伪造新一轮检查。
- 补交预检查失败原因进入诊断包，避免只看到旧验收报告而不知道本次补交为何停止。
- 更新说明中的接入标准，区分契约识别、从零创建、已有入口追加、公司已有结构兼容四种验证。

## 验证边界

登记识别与目录策略已取得新版原生实测证据。尚不能据此宣称第二大脑创建、Windows 修复或非技术用户体验已全部验收。组织接口测试使用模拟响应，不代表真实测试组织写入成功。本次未创建或写入任何 GitHub 测试组织，未操作用户原 sample 产物。
