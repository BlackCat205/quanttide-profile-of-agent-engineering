## 真实诊断输入

用户从 Windows 0.8.0 任务导出诊断包。本轮只读取诊断，没有代替用户写入 GitHub。诊断显示：

- `quanttide-intention-of-sample3-engineering` 的仓库创建、首次 `git ls-remote` 和克隆均成功；GitHub 创建回执包含仓库 ID、归属 ID 和完整名称。
- 第 12 项操作已经写好 `CHANGELOG.md`、`LICENSE` 并保存 `staged / executed-unverified` 阶段；尚未保存本地提交或推送阶段。
- 同一仓库的只读连接检测曾同时通过账号接口、远端版本和临时浅克隆。
- 五分钟后再次继续时，账号 API 和仓库 API 仍通过；额外的 `git ls-remote` 分别耗时约 22、21、42 秒后失败，后两次已使用进程内 HTTP/1.1。

因此本次暂停属于 Git 数据通道的间歇性故障，不是命名、文件规范、GitHub 身份或 HTTP/1.1 降级未生效。执行前重复使用 `git ls-remote` 是不必要的阻塞点。

## 修正

- GitHub 仓库身份、默认分支提交和标签改用登录后的 GitHub API 核验；`git` 网络保留给克隆、子模块传输和推送。
- 新增下载、文件写入、暂存和本地提交四类持久阶段恢复。恢复会核对仓库身份与远端提交、本地 HEAD、分支、origin、规则文件、工作流文件哈希和变更路径；完全一致才推进检查点。
- 0.4.2 仅兼容精确登记的 0.4.1 执行器 SHA-256。计划正文、确认记录和历史执行日志不改写；未知版本仍拒绝直接继续。
- 页面预检查失败时同步把执行日志记录为 `paused`，避免页面显示暂停而诊断仍显示 `running`。
- GitHub 空仓库的 HTTP 409 与网络/权限失败分开处理。
