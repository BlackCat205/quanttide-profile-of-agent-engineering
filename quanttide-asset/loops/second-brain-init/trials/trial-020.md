# 0.8.6：建仓回执丢失后的核对接续

日期：2026-09-13。UI 0.8.6，执行器保持 0.4.6；契约仅更新 ui_version。

## 问题证据

sample5 的 0.8.5 诊断包显示已完成 4/27 项，第 5 项实验室建仓请求连接中断。本任务没有获得该仓库创建回执，检查点仍为不存在。GitHub 只读元数据显示仓库在请求期间创建；随后三项连接检测通过。恢复操作因此被状态漂移检查阻止。

本次只读查询显示目标仍为只有 README 的初始提交（无父提交）。这不证明创建归属，也不替代用户电脑上的权限检查；不因同名或创建时间相近自动接管。

## 实现

复用已有严格初始仓库检查，将其从单一旧执行器扩展为当前及明确兼容版本。仅限 GitHub new-domain 中断的 ensure-repo、原检查点不存在且本机尚未下载的目标。只读核对仓库所属账号、写入权限、初始提交、唯一 README 的内容；有后续提交或其他文件拒绝接续。方案经页面确认后生成独立恢复任务，再检查身份与固定提交没有变化；不修改旧计划和旧执行日志，不立即推送。

恢复记录合并保留此前所有创建凭据、阶段与完成步骤，不再丢弃此前凭据。页面显示“核对并接续初始仓库”，从检查、确认到打开恢复记录均无需命令行。日志中有精确创建回执的现有自动恢复机制保持不变。

## 验证

定向中断恢复测试 16 项通过，2.118 秒。

新增端到端故障测试使用实际本地 bare Git 仓库与模拟 GitHub API：第 5 项创建成功并留下 README，但响应抛出网络错误；原流程暂停 4/27；再次恢复正确转入核对接续；页面预览、确认、打开恢复任务后完成 27/27 和最终技术检查。8 个目标仓库各创建一次，之前完成的操作不重复，旧日志字节保持不变，之前创建凭据仍存在。

完整回归 107 项全部通过，128.442 秒。命令：`python -m unittest discover -s quanttide-asset/loops/second-brain-init/tests -p "test_*.py" -v`。

Python 编译、JavaScript 语法、git diff --check 及资产契约入口检查通过。测试不向真实 GitHub 写入测试仓库。

## 真实环境边界

本轮实际在 Linux 运行本地 Git 与模拟 GitHub 故障测试；不宣称已在用户 Windows 上完成恢复。用户升级后应在原记录使用“检查接续方案”，核对初始骨架并确认，随后打开恢复记录继续。无法自动处理的内容变化仍必须暂停，不以跳过身份或内容检查换取通过。
