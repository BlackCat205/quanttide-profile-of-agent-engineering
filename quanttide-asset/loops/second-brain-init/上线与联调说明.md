# 当前交付与真实使用的边界（UI 0.4.0）

## 交付是什么

这是带中文网页向导的本机可运行工具，复用登记在资产配置中的执行器。它把填写需求、审阅方案、建立 Git 仓库、按规则检查和记录人工意见连起来。它目前不是已经部署在资产云上的多人在线插件，也不是免安装软件。

提交招聘任务时，可以提交完整程序包、START_HERE.md 使用说明、trials 内的测试记录，以及本说明。应标注“本地可运行，云端联调待完成”，不能宣称已经完成公司资产云上线。

## 已有功能与验收缺口

| 项目 | 当前实际情况 | 通过下一阶段验收的证据 |
| --- | --- | --- |
| 非技术操作 | 中文表单、方案解释、进度、七项规范检查、首页阅读、意见与报告；支持连续创建 | 一位未参与开发的同学在 Windows 独立完成两次创建，保存真实意见 |
| 仓库产物 | 本地真实 Git 仓库、提交、子模块与本地远端；每次创建独立测试总入口 | 在获准的 GitHub 测试组织创建领域，并在既有总入口中看到它 |
| 业务含义 | 用途、边界、英文名称由用户输入；程序检查结构 | 业务同学确认用途准确、分工合理、资料能找到 |
| 资产云接入 | 资产契约登记、适配入口调用；尚无在线宿主联调证据 | 从公司指定资产云入口启动、拿到任务状态、打开真实产物 |
| 场景范围 | 网页支持新建领域；其他维护场景仍走配置入口 | 公司明确首版只需新建，或补齐要求的其他界面 |
| 公司多人使用 | 当前是本机单用户服务 | 完成公司账号与权限、共享任务存储、同一仓库并发控制、任务恢复和操作留痕验证 |

## 真实 GitHub 联调怎么推进

1. 公司指定一个可用于测试的 GitHub 组织、负责操作的账号，以及允许操作的测试总入口。当前执行器会创建公开仓库，测试资料不得包含内部敏感内容。若要求私有仓库，需要先调整实现和测试。
2. 维护者在实际运行电脑配置 Git、GitHub CLI 和账号授权，并验证对测试组织和总入口的权限。不要把密码或访问令牌粘贴到聊天或需求表单。
3. 维护者启用 GitHub 模式。用明确的测试简称生成方案，检查所有目标仓库、已有总入口和写入范围；审阅具体方案后再执行。不要直接把生产组织当成试验场。
4. 在 GitHub 网站核对仓库、提交、子模块和总入口导航；再创建第二个不同领域，确认两者均能从同一个总入口找到。记录组织、仓库链接、提交编号、结果与问题。
5. 真实账号执行、Windows 操作和人工验收分别记录。自动化模拟反馈不能代替这些记录。

当前尚未取得本次联调的测试组织信息和可用授权，因此没有执行上述云端写入。提供组织名称只用于确定接入范围，执行前仍应审阅工具生成的具体写入方案。

## 资产云联调怎么推进

需要公司给出实际资产云入口、测试环境和支持的插件调用方式。现有登记文件本身不等于在线平台已经加载插件；已核对的资产云源码版本也不能证明公司线上环境具备相同能力。

公司维护者需要确定：由资产云调用安装在电脑上的工具，还是由云端服务执行任务。选定后实现启动入口、字段传递、执行状态与产物链接回传，并在测试环境跑通一次真实流程。不能将当前仅监听本机的网页服务直接公开到互联网充当公司服务。

## 谁需要做什么

- 非技术同学：填写需求、看懂方案、阅读生成首页、记录真实意见；日常操作应在页面内完成。
- 维护者：首次安装、账号授权、故障处理与更新；当前 Python/Git 依赖仍需维护者协助。
- 公司平台负责人：提供测试组织与资产云入口，明确首版接入范围和发布条件。

达到公司内部小范围试用，至少还需真实 Windows 试用与授权测试组织联调；宣称资产云已接入，必须再取得真实宿主调用证据。

## 0.4.0 已补充的工程检查

新增按需公开 GitHub 只读调查，展示目标、时间、提交与采用章程版本；真实查询证据见 trials/public-survey-040/report.json。网页新建禁止自动复用同名配套仓库，执行前保存复核证据，执行器每步比较仓库检查点。

当前只读调查未登录，只能观察公开可见资源，不能证明不可见仓库不存在。在线章程发生变化或无法核对时，网页 GitHub 写入方案暂停；不会自动替换本地规则。旧 CLI 维护场景不自动调用这项网页调查。

每一步检查与后续写入之间仍有时间间隔，多仓库操作不是数据库事务。正式并发使用仍需要公司侧任务协调；不要将本版描述为已解决所有并发冲突。未完成真实 GitHub 写入、Windows 真人及资产云调用验收。
