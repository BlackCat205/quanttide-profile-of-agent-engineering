# 任务要求与验收边界（UI 0.6.1）

上级给出的是验收要求，不是对本产物的通过评价：可以先在自己的测试组织进行；资产云按 `.quanttide` 契约登记接入。不再把在线部署、资产云 API 或公司生产组织联调列为本课题的必需接入条件。

## 接入证据

资产云源码：quanttide/qtcloud-asset，提交 519b4e01c5f7c35f83c2311d093ac4d19ae6f338。当前 Rust 解析器从工作目录向上查找 `.quanttide/asset/contract.yaml`，读取 assets、skills、validation。旧 docs/user/config.md 中 contracts.yaml 的说明与此实现不同，不能直接照抄。

本版使用 `cargo build --locked` 编译原生 CLI，对最新版登记重新运行 config、scan、validate，并保留原始输出，见 [本版测试](trials/trial-011.md)。这不是旧版输出的转录。

- config 显示 6 个登记资产和 1 个 second-brain-init v0.3.1 技能，证明配置可读取、条目可列出。
- validate 根据登记的策略检查扫描到的 5 个一级目录。6 是登记条目数，5 是目录数，不能混用。
- 另检查登记的文件路径和技能程序入口存在；原生 config 本身不完成此项检查。
- config 不执行技能，不能证明 GitHub 创建或业务内容正确。原生 run 当前是归档流程，不能当成创建技能的通用调度器。
- 原生 validate --json 在存在失败项时也可能退出码为 0，验收必须读取 failed_assets；本次增加缺少必需目录与格式错误反例。

因此现有证据支持“本版满足所测试 CLI 版本的契约识别与目录策略要求”；最终是否通过由上级验收，不代替上级作评价。

## 测试空间

网页支持本人个人账号，或当前登录者担任所有者的公开测试组织。填写“我管理的测试组织”后，创建前核对组织成员状态 active 和角色 admin；无法确认即停止。此入口不会自动创建组织，不允许据此推断公司组织授权。

从零创建无需复制公司第二大脑；测试已有入口追加需要已有结构，可以用第一次创建的测试入口；验证公司现有结构兼容时，才需要相关仓库测试副本，并核对其中指向公司仓库的连接。

## 尚待完成

真实 Windows 补交/新建的完整验收、真实测试组织操作、非技术同学独立完成操作仍待实际证据。当前未提供测试组织名称，因此没有替用户创建组织或向组织写入。

多仓库操作不是事务；跨机器并发、分支规则和部分写入仍可能需要维护者处理。已知旧 sample 任务可用定向 LICENSE 补交；其他旧版未完成任务不自动跨版本迁移。在线部署或公司多人 PR 审批可以另行扩展，不作为当前契约接入的前置条件。
