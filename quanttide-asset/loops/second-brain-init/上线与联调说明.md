# 当前交付与真实使用的边界（UI 0.5.0）

## 交付形态

这是带中文网页向导的本机工具，调用资产登记配置中的执行器。提供本地 Git 流程与个人公开 GitHub 登录、创建、提交入口；不是公司资产云多人在线服务，也不是免安装 EXE。

## 当前能力与验收边界

| 项目 | 当前实现 | 尚需实际证据 |
| --- | --- | --- |
| 个人 GitHub | 官方 CLI 浏览器授权、本人账号创建、自定义总入口、执行确认 | 真实 Windows 授权与创建记录 |
| 连续创建 | 每次从远端调查，支持同一总入口追加不同领域；不覆盖重名领域 | 真实 GitHub 两轮提交和入口链接 |
| 工程检查 | 账号 ID 绑定、仓库 ID 与提交快照、执行前和每步复核、逐步状态、验收链接 | 实际权限、网络、分支规则下的联调 |
| 非技术体验 | 中文表单、命名提示、逐项标准、导出报告 | 非开发同学独立使用并记录意见 |
| 公司资产云 | 资产契约登记、适配入口、本机调用 | 公司宿主真实调用与状态、产物回传 |

自动化中的 GitHub 传输模拟不是真实云端提交；本地 Git 提交和子模块可以真实测试。不同环境证据必须分别标注。

## 个人测试先行

无需公司先提供测试组织。按 START_HERE.md 用个人账号建立干净测试总入口，先执行一次，再追加第二个领域，核对 GitHub 实际文件与提交。当前只创建公开仓库，使用测试内容。

网页版仅允许当前登录者的个人账号；CLI 保留组织路径，但不表示公司组织已经授权或联调。Fork 公司总入口后，已有链接可能仍指向公司，需要单独核对兼容性。不会自动迁移或维护所有量潮仓库。

## 资产云接入仍需要公司配合

公司需要说明实际测试入口、插件加载和调用方式、参数、身份和权限要求，以及状态和产物如何回传。确定由本机还是云端执行后，才能实现对应接入并记录宿主调用证据。个人 GitHub 联调成功不能代替资产云验收。

## 可靠性限制

GitHub 查询按需进行，不持续监控全组织；404 和请求失败不能证明名称可用。网页写入前比较在线章程与采用版本，不一致或无法读取时停止。计划绑定程序版本、账号与目标归属；更新程序或切换账号后重新生成方案。

每步检查与后续写入之间仍有间隔。多仓库操作不是事务，不自动删除远端产物回滚；发生部分写入时可能需要维护者恢复。一个本机服务会阻止同时执行多个 GitHub 创建任务，不等于跨电脑并发协调或生产上线保障。

Git 凭证仅按进程配置为使用 GitHub CLI；不修改用户全局 Git 设置。官方授权可能受公司策略或网络限制，登录成功不提前证明仓库创建和分支推送权限。
